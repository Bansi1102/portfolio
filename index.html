How a clinical note becomes billing codes

A simplified view of how the pieces I built fit together.

  1. SOAP note inRaw clinical text arrives at the API

  6. Codes outFeedback is stored to improve later results

Selected work

Built at Panva Technology Solutions for a revenue cycle management platform.

Payer-policy document Q&A

tiktoken, SentenceTransformers, FAISS, Llama 3.1 8B (Ollama)

A RAG pipeline that ingests PDFs, chunks them by tokens, and answers policy questions from the source text with citations.

Answers stay tied to the documents instead of free-form model output.

CPT/ICD extraction with per-user RAG

FAISS, JSONL feedback store, Azure OpenAI

Replaced a TF-IDF and nearest-neighbour retriever with a per-user RAG design. Feedback is stored, and earlier responses are reused when similarity is above a set threshold.

Fewer redundant LLM calls, with Azure OpenAI as a fallback.

Fine-tuned Llama 3.1 models

LoRA, ~50k JSONL training examples

One model extracts ICD/CPT codes from SOAP notes. Another validates billed CPT codes against NCCI guidelines. Early runs underfit, so I expanded the dataset.

~97% validation accuracy on NCCI validation, backed by a rule engine that overrides the model.

Revenue cycle prediction models

XGBoost, scikit-learn, Flask, SQLAlchemy, SQL Server

Models for payment percentage, payment timing and patient aging risk, saved with joblib and served from a Flask service. I diagnosed and fixed both overfitting and underfitting across models.

Automated predictions replaced manual due-date and collections-risk estimates.

Secure production deployment

Gunicorn, systemd, NGINX, JWT, Presidio, spaCy

Flask APIs run on an Azure Linux VM behind an NGINX reverse proxy, using Unix sockets and JWT authentication. Patient data is redacted before any text reaches an LLM.

Daily model monitoring

cron, scikit-learn metrics

A scheduled pipeline retrains the revenue models and tracks R², MAE and training record count.

Model reliability can be checked without manual runs.
